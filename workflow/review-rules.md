# Review Rules

## Review Outcomes

Mastermind and QA use three outcomes:

- `accept`: work satisfies the task brief and verification requirements.
- `refine`: work is directionally correct but needs specific corrections.
- `reject`: work does not satisfy the task or conflicts with project direction.

## QA Review Bar

QA checks:

- task brief alignment
- design brief alignment
- API contract alignment, required only for front-end/back-end integration tasks
- changed files
- commands run
- responsive behavior
- error and empty states
- accessibility basics
- regression risk
- human checks needed

## Mastermind Review Bar

Mastermind checks:

- whether the assigned mission was completed
- whether each agent stayed inside ownership boundaries
- whether decisions were logged
- whether conflicts are resolved or tracked
- whether QA evidence supports the recommendation
- whether Human Operator action is needed

## Refinement Rule

A refinement request must state the exact issue, the required correction, allowed files or sections, verification required, and return format.

## Acceptance Rule

Only the Mastermind marks a task accepted in `TASKS.md`.
